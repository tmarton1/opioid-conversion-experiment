Methods

This document describes the experimental design, implementation, analysis pipeline, and statistical methods used in the opioid-conversion-experiment study. All source code and data are available at https://github.com/tmarton1/opioid-conversion-experiment.

Methods Overview

Study Design

We evaluated the ability of 13 large language models (LLMs) to perform equianalgesic opioid dose conversions — a common and safety-critical clinical task. Each model was presented with a source opioid, a dose, and a target opioid, and asked to calculate the equivalent dose in the target formulation. Two complementary experimental paradigms were used:

(1) Clinical vignette conversions across 20 clinical scenarios (e.g., post-surgical cancer patients, pediatric burn patients, elderly hip-fracture patients), each re-stated in 4 distinct phrasings plus 1 empty-text control, yielding 100 vignettes in total.

(2) Random-dose conversions across 49 directed opioid-pair conversions drawn from 20 opioid substances (administration route included), comprising 15 bidirectional pairs tested in both directions and 19 one-directional conversions to oral morphine. Each opioid pair was assigned a clinician-defined priority score (priority 1 or 2) reflecting clinical relevance. Doses were sampled log-uniformly from an oral-morphine-equivalent range of 10–120 mg. All random-dose prompts used the standard unit mg/day. A subset of 15 pairs was additionally tested with a non-daily target unit (mg/4 hours) to isolate time-unit conversion errors; in those trials, the prompt optionally included an explicit dosing-unit explanation (e.g., "the dose over 4 hours should be 1/6 the daily dose").

Prompt conditions were factorially varied to test the effect of providing a published reference table — the Nielsen equianalgesic conversion table (Nielsen et al., 2014). We deliberately included opioid pairs that require extra reasoning steps beyond a simple lookup in the Nielsen table: pairs whose target is not oral morphine require chaining two conversion factors through a morphine-equivalent intermediate, and pairs with non-daily units require an additional time-unit conversion.

Accuracy was assessed as the ratio of observed to expected dose (ratioobs/exp). Two clinically-motivated accuracy ranges were defined: tight (0.85–1.15× expected, i.e., ±15%) and broad (0.60–1.70× expected). Each model × item × condition combination was repeated multiple times (median 7 for vignettes; median 10 for random doses) to quantify response variability. All API calls used temperature = 0.0.

Implementation & Code Organization

The entire experimental pipeline — from prompt construction through data collection, statistical analysis, and figure generation — was implemented in Python and is publicly available at https://github.com/tmarton1/opioid-conversion-experiment. The experiment code was developed with the assistance of GPT-4.1 and Claude Sonnet 4.5; the analysis and visualization code was developed with Claude Opus 4.6 via GitHub Copilot. The implementation uses Python 3.14.0, pandas 2.3.3, SciPy 1.16.3, NumPy 2.3.4, statsmodels 0.14.6, and Bokeh 3.8.1. The repository is organized into five packages:

  • common/ — Opioid data models, the Nielsen conversion table, unit-aware dose conversion logic, and the opioid-pair generator.
  • experiment/ — Prompt construction, API routing, experiment runners for both random-dose and clinical-vignette paradigms.
  • resources/ — The Nielsen equianalgesic table (JSON), scenario definitions, and vignette text.
  • analysis/ — Statistical analysis modules that read raw result CSVs and produce summary statistics, test results, and derived CSVs.
  • visualize/ — Visualization code generating publication-ready figures.

API Infrastructure & Data Collection

All 13 models were queried through the OpenRouter API, which provides a unified interface to models from OpenAI, Anthropic, Google, Mistral, Meta, Cohere, AI21, Alibaba (Qwen), and DeepSeek. Each API call used temperature = 0.0 and a maximum token budget of 500 tokens. Models were instructed to return their answer as a Python dictionary literal ({"calculated dose": value}), and the numeric dose was extracted from the response text via regular expression.

The 13 models tested were: GPT-4.1, GPT-4.1-mini, GPT-3.5-turbo (OpenAI); Claude 3.5 Sonnet (Anthropic); Mistral Large, Mixtral 8×22B (Mistral); Gemini 2.5 Pro, Gemini 2.5 Flash (Google); Command R+ (Cohere); Jamba Large (AI21); Qwen 2.5 72B (Alibaba); Llama 3.3 70B (Meta); and DeepSeek Chat (DeepSeek).

Results were saved row-by-row to CSV files during each experiment run. The random-dose experiment produced 9,667 rows for 13 models (results/experiment_results.csv; 26,871 total including preliminary models), the vignette experiment produced 27,166 rows for 13 models (results/reworded_vignettes_results.csv; 28,814 total), and the dosing-unit experiment produced 9,743 rows for 13 models (results/explain_units_experiment_results.csv; 10,493 total).

Analysis Pipeline

Raw result CSVs were processed by analysis modules in the analysis/ package. Each module reads the appropriate experiment CSV(s), groups trials by model, opioid pair (or vignette), and condition, computes accuracy rates and summary statistics, performs the relevant statistical tests, and writes the results to derived CSV files in the results/ directory. Vignette analyses group by vignette_id and scenario_key to distinguish wording variants within the same clinical scenario. This two-stage design (experiment → CSV → analysis → CSV) ensures full reproducibility: all statistical results reported below can be regenerated from the raw data using the analysis modules.

Statistical Test Glossary

The following tests were used throughout the analyses. Each entry describes the test, its statistical justification, and how it was applied in this study. Specific test results are detailed in the per-figure sections below.

Cochran–Mantel–Haenszel (CMH) Test

Purpose. To rank-order models by pairwise accuracy comparisons while controlling for the hierarchical structure of the data.

Why CMH. The conversion data has a hierarchical structure: individual trials are nested within conversion items (opioid pairs or vignette scenarios). A simple pooled comparison would treat every trial as independent, when in fact trials within the same item are correlated. The CMH test respects this nesting by forming a separate 2×2 table within each conversion item, then testing whether one model is consistently more accurate across all strata — pooling evidence across independent item-level comparisons rather than across non-independent trial-level observations. The one-sided formulation tests whether model A is systematically more accurate than model B. Because the number of pairwise comparisons is large, all p-values are Bonferroni-corrected.

Application. We computed CMH tests for every pair of models in 5 ranking analyses, with stratification counts ranging from 15 to 49 strata depending on the item set. Results are stored in the ranking_*_pairs.csv files.

Wilcoxon Signed-Rank Test

Purpose. To test whether a prompt augmentation (e.g., providing the Nielsen reference table, adding a dosing-unit explanation) significantly changes a model's accuracy on matched conversion items.

Why Wilcoxon. Each model is tested on the same set of opioid pairs (or scenarios) under two conditions, yielding naturally paired observations. The Wilcoxon signed-rank test is the appropriate non-parametric paired test when the distribution of differences may be non-normal. It tests H₀: the median difference in accuracy between conditions is zero. We perform this test separately for each model and pooled across all models.

Application. Wilcoxon tests are computed in 18 separate comparison analyses (e.g., Nielsen effect on vignettes, Nielsen effect on random doses, dosing-unit explanation effect, OME-stratified subsets). Each CSV in the wilcoxon_*.csv family contains per-model test results plus a POOLED row aggregating across all models.

Fisher's Exact Test (with Bonferroni Correction)

Purpose. To test whether the accuracy rate on a specific conversion item differs between two prompt conditions for a given model.

Why Fisher's exact. At the individual model × item level, each condition yields only ~7–10 binomial trials (repetitions). With such small cell counts, the χ² approximation is unreliable; Fisher's exact test computes the exact hypergeometric probability. Because hundreds of such tests are performed in parallel (one per model × item combination), Bonferroni correction is applied within each model's family of items to control the family-wise error rate.

Application. Fisher's exact tests are computed in the comparison_*.csv files, one per condition-pair analysis. The tight_result and broad_result columns indicate whether condition A or B was significantly better, or whether no significant difference was found.

Intraclass Correlation Coefficient — ICC(1,1) with F-test

Purpose. To quantify how much of the variance in model responses is attributable to vignette wording (between-vignette variance) versus stochastic noise (within-vignette variance). A high ICC indicates that the model's answer depends strongly on how the question is phrased, even when the underlying clinical scenario is identical.

Why ICC(1,1). The ICC(1,1) from a one-way random-effects ANOVA is the standard measure of rater agreement/consistency when the grouping factor (vignette wording) is treated as a random sample from a population of possible phrasings. The associated F-test evaluates H₀: σ²between = 0, i.e., all vignette wordings produce statistically indistinguishable response distributions.

Application. ICC is computed for each of the 260 model × scenario cells (13 models × 20 scenarios), with k = 4 vignettes per scenario. The F-test rejects H₀ in 215/260 cells, indicating pervasive wording sensitivity. Results are in results/icc_analysis.csv.

Mann–Whitney U Test (Bonferroni-corrected)

Purpose. To identify specific pairs of vignette wordings whose response distributions differ significantly within a given model × scenario cell.

Why Mann–Whitney U. Within each ICC cell, the k vignettes' response distributions are compared pairwise. Because the responses are log-ratios with potentially skewed distributions and small per-vignette sample sizes (~7 repetitions), the non-parametric Mann–Whitney U test is preferred over a parametric alternative. Bonferroni correction is applied across the (k choose 2) pairs within each cell to control family-wise error.

Application. Pairwise Mann–Whitney results are summarized in the sig_pairs and total_pairs columns of results/icc_analysis.csv.

Spearman Rank Correlation (ρ)

Purpose. To test monotonic associations between continuous measures — in particular, whether scenarios with higher total response variance also have higher ICC (i.e., more wording-driven variance), and whether more accurate models tend to have lower response variance.

Why Spearman. Spearman's ρ is a non-parametric rank-based correlation that does not assume linearity or normality. It is robust to outliers and appropriate when the relationship may be monotonic but not necessarily linear. The associated p-value tests H₀: ρ = 0 (no monotonic association).

Application. (1) Per-model and overall correlation between scenario total variance and ICC (overall ρ = 0.375, n = 260 model × scenario observations). (2) Correlation between model-level accuracy and mean total variance across models (n = 13). (3) Cross-experiment Spearman correlations between matched-pair accuracies across experimental paradigms. Results are in results/variance_icc_spearman.csv and results/cross_experiment_matched_spearman.csv.

Binomial Sign Test

Purpose. To test whether the per-model Spearman ρ values (variance vs. ICC) are consistently positive across models — i.e., whether the association between total variance and wording sensitivity is a general phenomenon rather than an artefact of a few outlier models.

Why the sign test. The sign test is the simplest non-parametric test for a consistent direction: it counts the number of positive vs. negative values among independent observations and compares to a binomial distribution with p = 0.5. It makes no assumptions about the magnitude or distribution of the ρ values, only their sign.

Application. Of the 13 per-model ρ values, 12 are positive and 1 is negative, yielding a sign-test p = 0.003, confirming that the variance–ICC association is consistent across models.

Kendall's Coefficient of Concordance (W)

Purpose. To test whether different models agree on which vignette wordings produce higher or lower responses within each scenario. A significant W would indicate that wording effects are not merely model-specific noise, but reflect some shared sensitivity to phrasing.

Why Kendall's W. Kendall's W is the standard non-parametric measure of inter-rater agreement when multiple raters (here, models) rank the same set of items (vignette wordings) within each scenario. It ranges from 0 (no agreement) to 1 (perfect agreement). The associated χ² approximation tests H₀: W = 0.

Application. W is computed for each of the 20 scenarios, with 13 models as raters ranking 4 vignettes by mean log-ratio. 0/20 scenarios reached significance (p < 0.05), indicating that wording sensitivity is largely model-specific rather than reflecting a shared vulnerability to particular phrasings. Results are in results/kendall_w_vignettes.csv.

Pearson's χ² Test of Independence

Purpose. To test whether accuracy category and response precision (coefficient of variation) are statistically associated for each model — i.e., whether models that are imprecise on a given item also tend to be inaccurate.

Why χ². The test cross-tabulates two categorical variables (accuracy bin × CV bin) in a contingency table and tests H₀: the row and column variables are independent. The Pearson χ² statistic follows an approximate χ² distribution with (r−1)(c−1) degrees of freedom when expected cell counts are sufficiently large (≥ 5). When minimum expected counts fall below this threshold, a warning is flagged. For one model (Gemini 2.5 Flash), data sparsity precluded a valid test and χ² is reported as N/A.

Application. Per-model χ² tests on the vignette CV × accuracy grid found 2/12 models with a significant association. Additionally, 3×3 grid independence tests were computed for accuracy × variance, variance × CV, and variance × ICC grids across all models, stored in results/grid_independence_tests.csv.

Linear Regression (Dose-Dependence)

Purpose. To test whether model conversion errors are dose-dependent — i.e., whether the log(observed coefficient) changes systematically with the expected dose level. A significant slope would indicate that the model's conversion factor is not constant across doses, suggesting a failure to apply linear proportional conversion.

Why linear regression. The dose-dependence hypothesis is naturally expressed as a linear relationship: log(ratioobs/exp) = β₀ + β₁ × dose + ε. Ordinary least-squares regression directly tests H₀: β₁ = 0 via a t-test on the slope. The R² statistic quantifies what fraction of the log-ratio variance is explained by dose.

Application. Regression was fit for each model × opioid pair × condition combination under the naive condition. Of 1563 valid regressions, 279 showed a significant dose-dependent slope (p < 0.05). Results are in results/pair_model_analysis.csv.

Weighted t-test (Log-Space)

Purpose. To test whether a model's consensus conversion coefficient (the precision-weighted mean across repetitions) differs significantly from the expected literature value for each opioid pair or vignette scenario.

Why weighted t-test in log-space. Conversion coefficients are inherently ratio-scale and right-skewed; log-transformation produces an approximately normal distribution suitable for a t-test. Weighting by the inverse variance of each repetition's log-ratio ensures that more precise estimates contribute more to the consensus. The test statistic is t = (x̄w − μ₀) / SEw, where μ₀ = 0 in log-space (i.e., perfect agreement with the expected coefficient).

Application. Consensus t-tests are computed (1) per model × opioid pair in results/opioid_pair_consensus.csv, and (2) per model × vignette scenario in results/vignette_model_consensus.csv.
