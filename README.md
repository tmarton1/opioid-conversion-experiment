# Opioid Conversion Experiment

## Purpose

This repository contains the code and results for an experiment evaluating how large language models (LLMs) perform opioid dose conversions — specifically, converting from one opioid formulation to an oral morphine equivalent (OME) or another opioid — under systematically varied **prompting conditions**. How good are the various available language models at this task when not prompted with conversion rates?  If they are inaccurate, are they uncertainly or confidently wrong?  Does changing what information is given to the model (no context, Nielsen conversion table, worked examples, explicit unit instructions) measurably improve accuracy and reliability?

Results are compared across 13+ frontier models from OpenAI, Anthropic, Mistral, Google, Cohere, AI21, Qwen, Meta-LLaMA, and DeepSeek.

---

## Workflow

The repository follows a five-stage pipeline from raw reference data to final deliverable documents:

1. **Resources** (`resources/`) — Nielsen OME conversion tables and clinical vignette definitions provide the ground-truth data used throughout.
2. **Run experiments** (`experiment/`, `orchestration/run_experiments.py`) — LLM prompts are constructed and dispatched across all model × condition × opioid-pair combinations. Raw trial results (one row per LLM call) are written to CSVs in `results/`.
3. **Analyze** (`analysis/`, `orchestration/run_analysis.py`) — The raw CSVs are processed: accuracy metrics are computed, comparisons are run across conditions and batches, ICC/Kendall's W agreement statistics are calculated, and cross-experiment matched analyses are performed. Derived CSVs are written back to `results/`.
4. **Visualise** (`visualize/`) — Individual interactive Bokeh figures (heatmaps, bar charts, batch summaries, etc.) are generated from the analysis CSVs and saved as standalone HTML files in `figures/`.
5. **Summarise** (`orchestration/generate_summaries.py`) — The final deliverable documents are assembled in `summary_w_figures/`: a multi-table accuracy summary HTML/PDF (`SummaryTablesBuilder`) and a full annotated figure report combining every publication figure with its narrative description (`ComprehensiveFigureBuilder`). Numeric annotations in the PDF are populated from `summary_w_figures/figure_stats.json` (generated by `orchestration/extract_figure_stats.py`). This folder is the primary entry point for reading the results.

## Experiments

Each experiment crosses **opioid input types** with **prompt conditions** and is run across all models with multiple repetitions per combination. The metric of interest is how often the model's answer falls within a tight (±15%) or broad (±40%) range of the ground-truth answer calculated from Nielsen conversion factors.

### Experiment Types

| Name | Description | Class | Output CSV |
|---|---|---|---|
| **Random-dose opioid pairs** | Abstract pairs: "Convert X mg/day oral hydromorphone to oral morphine equivalent." Dose is sampled randomly on a log-uniform scale. | `Experiment` | `results/experiment_results.csv` |
| **Vignette / scenario** | Clinical narrative vignettes: the dose is embedded in a patient story. Four reworded versions of each scenario exist, plus a "bare" empty-text variant. | `ScenarioExperiment` | `results/reworded_vignettes_results.csv` |

### Prompt Conditions

Each experiment run applies one combination of these Boolean flags:

| Flag | Effect on prompt |
|---|---|
| `include_nielsen=False/True` | Append the full Nielsen conversion table to the prompt |
| `include_examples=False/True` | Include worked conversion examples |
| `ask_for_units=False/True` | Instruct the model to state the output unit explicitly before answering |
| `explain_units=False/True` | Provide explicit unit definitions (e.g., explain mg/day vs mg/4 hours) |

The baseline ("naive") condition has all flags `False`. The notebook and scripts test various combinations of these to measure their marginal effect.

### `common/` — Shared Domain Objects

#### `opioid.py`
Core domain model.

- **`Opioid`** *(dataclass)*: Represents one opioid formulation. Fields: `administration_method` (e.g. `"oral"`, `"iv"`), `substance` (e.g. `"morphine"`, `"fentanyl"`), `unit` (auto-resolved from Nielsen data if not supplied). Method: `to_str()`.
- **`OpioidPairGenerator`**: Generates lists or pairs of `Opioid` objects filtered by priority.
  - `generate_opioid_list_or_pairs(pairs, use_permutations)` — returns combinations or permutations of filtered opioids.
- **`dict_to_opioid(d)`** *(function)*: Constructs an `Opioid` from a dict, ignoring extra keys.
- **`opioid_list_to_str(opioids)`** *(function)*: Serialises an `Opioid` or list to a comma-separated string.

#### `conversion_service.py`
Ground-truth dose arithmetic using Nielsen data.

- **`ConversionService`**:
  - `generate_random_dose(from_opioid, dose_range)` — samples a log-uniform dose in OME space and back-converts to the source opioid's unit.
  - `calculate_expected_dose(dose_from, from_opioid, to_opioid)` — computes the correct target dose via OME.
  - `calculate_expected_dose_multiple(from_opioids_doses, to_opioid)` — same for multi-opioid inputs (e.g. a patient on two opioids simultaneously).

#### `models.py`
- **`CONSISTENT_MODELS`** *(list)*: The canonical list of models used across all experiments, with full `provider/name` identifiers.

#### `opioid_unit_finder.py`
- **`OpioidUnitFinder`**: Looks up the dosing unit of an opioid from a CSV.
  - `get_unit(opioid_col, opioid_name, unit_col)` — returns the unit string.

### `experiment/` — Experiment Orchestration

#### `prompt_service.py`
Prompt construction and LLM querying.

- **`PromptedOpioidConversion`**: Core class for one conversion trial.
  - Holds opioid identities, dose, model, prompt flags, and stores the model's response.
  - `initialize_client()` *(classmethod)* — sets up OpenAI, OpenRouter, Anthropic, Groq, and Google clients once.
  - `generate_prompt(prompt_service)` — builds the text prompt according to the active flags.
  - `ask_model()` — dispatches to the appropriate API client, stores `observed_to_dose` and `ratio_observed_expected`.
  - `_query_openrouter()`, `_query_openai()`, `_query_anthropic()`, `_query_groq()`, `_query_google()` — provider-specific query methods.
  - `_extract_calculated_dose(response_text)` — regex extraction of the numeric answer.
  - `_is_openrouter_model(model_id)` *(staticmethod)* — routing helper.
- **`PromptService`**: Constructs prompt strings for different conditions.
  - Accepts a `ConversionService` and builds prompts with optional Nielsen table, examples, unit explanations.

#### `experiment.py`
Runs the random-dose opioid-pair experiment.

- **`Experiment`**:
  - `__init__(opioid_pairs, prompt_conditions, models, repetitions, ...)` — builds the Cartesian product of pairs × conditions × models.
  - `run()` — iterates all combinations × repetitions, calls `ask_model()`, appends rows to CSV.
  - `add_result_to_csv(result)` — thread-safe CSV append with auto-header.
  - `_get_next_experiment_id()` *(staticmethod)* — incremental ID from `experiment_id_counter.txt`.
- **`CSVWriteError`**: Custom exception for CSV write failures.

#### `scenario.py`
Clinical vignette scenarios.

- **`Scenario`**: Wraps a vignette dict (text, opioids, dose distribution, derived values).
  - `sample_dose()` — randomly samples from the dose distribution.
  - `fill_text(sampled_dose)` — substitutes `{{placeholder}}` tokens in the vignette text.
  - `build_from_opioids_doses(sampled_dose)` — constructs `[(Opioid, dose), ...]` from single or multi-opioid scenarios.
- **`ScenarioPromptedConversion`** *(extends `PromptedOpioidConversion`)*: Ties a `Scenario` to a prompted conversion. Fills text, samples dose, and initialises the parent with the appropriate opioid/dose fields.

#### `scenario_experiment.py`
Runs the vignette experiment.

- **`ScenarioExperiment`** *(extends `Experiment`)*:
  - `__init__(scenarios, prompt_conditions, models, repetitions, ...)` — builds the Cartesian product.
  - `run()` — iterates all combinations × repetitions, writes richer result rows (vignette_id, scenario_key, has_vignette_text, multi-opioid fields).
  - `add_result_to_csv(result)` — CSV append with vignette-specific fieldnames.

### `resources/` — Reference Data

#### `nielsen_data.py`
- **`NIELSEN_CONVERSIONS`** *(module-level dict)*: Loaded at import from `nielsen_ome.json`. Key = `"administration_method_substance"`, value = `{conversion_factor, unit, priority}`.
- **`load_nielsen_conversions(json_path)`** *(function)*: Parser.
- **`NielsenDataCSVConverter`**: Converts the JSON to `nielsen_data.csv`.
  - `convert_to_csv()`
- **`NielsenDataPriorityUpdater`**: Updates priority fields in the JSON.

#### `nielsen_ome.json`
Conversion factors and dosing units for each opioid formulation, based on Nielsen et al. oral morphine equivalents.

#### `original_vignettes.json` / `reworded_vignettes.json`
Clinical scenario vignettes. Each entry specifies `vignette_id`, `scenario_key`, `text`, `from_opioid`, `to_opioid`, dose distribution, derived value expressions, `has_vignette_text`.

#### `build_scenarios.py`
- **`build_scenarios(vignettes_path, verbose)`** *(function)*:
  1. Validates that all vignettes within a `scenario_key` share identical conversion parameters.
  2. Adds `has_vignette_text` field to each vignette.
  3. Creates a "bare" empty-text vignette for each scenario (used as the no-text baseline).

#### `scenario_vignettes.py` / `vignette_results_json.py`
Helper utilities for loading and filtering vignette data.

### `analysis/` — Statistical Analysis

#### `analysis_utils.py`
Top-level pipeline orchestration.
- **`processing_pipeline(input_csv, output_csv, variable_model_csv, consensus_csv, mode)`** — runs the full post-processing pipeline: add OME column → harmonise model names → compute per-(unit, model) stats → compute consensus.
- **`add_ome_column(input_csv, output_csv)`** — adds boolean `ome` column indicating oral morphine involvement.

#### `prefix.py`
Model name normalisation.
- **`harmonize(name)`** — adds missing provider prefix using `MODEL_PREFIXES` and `MODEL_ALIASES`.
- **`harmonize_model_names(csv_path, output_path, model_column)`** — applies `harmonize` to an entire CSV.

#### `opioid_pair_model_result.py`
Per-(opioid-pair × model × prompt condition) statistics.
- **`OpioidPairModelResult`**:
  - `calculate_coefficients()` — mean, std, CV of observed/expected ratios (in log space).
  - `perform_regression()` — regresses log-coefficient on expected dose; computes R².
  - `calculate_weights()` — `f = exp(-0.1 * R²)`, weight = `f / (log_std² + ε)`.
  - `calculate_proportion_within_range(lower, upper)` — tight/broad accuracy.
  - `process_all_combinations(csv_file, output_file, ...)` *(classmethod)* — batch-processes all groups in a CSV.

#### `opioid_pair_consensus.py`
Weighted consensus across models for a given opioid pair + condition.
- **`OpioidPairConsensus`**:
  - Computes weighted-mean log-coefficient, consensus variance, and between-model heterogeneity.
  - `process_all_combinations(...)` *(classmethod)* — batch consensus over all pairs.
  - `update_pair_model_analysis(...)` *(classmethod)* — back-annotates pair-model CSV with consensus info.

#### `vignette_model_result.py`
Per-(vignette × model × prompt condition) statistics.
- **`VignetteModelResult`**:
  - `calculate_dose_stats()` — mean, std, CV of observed doses (in log space).
  - `calculate_weights()` — precision-based weight.
  - `calculate_proportion_within_range(lower, upper)` — tight/broad accuracy.
  - `process_all_combinations(...)` *(classmethod)*
- **`VignetteModelConsensus`**: Cross-model consensus for each vignette condition.

#### `scenario_model_result.py`
- **`ScenarioModelResult`**:
  - `calculate_scenario_stats(group_df)` *(staticmethod)* — aggregates vignette-level rows into scenario-level stats (weighted mean, between- and within-vignette variance).

#### `batch.py`
Data containers for grouped experiment results.
- **`PairPromptKey`** / **`VignettePromptKey`** *(frozen dataclasses)*: Hashable keys identifying a prompt condition slice.
- **`Batch`** (base): Lazy-loading container. Reads CSVs only when `.model_data`, `.consensus_data`, or `.experiment_data` are accessed.
- Subclasses (**`PairBatch`**, **`VignetteBatch`**, etc.) specialise filtering and key logic.

#### `batch_comparison.py`
- **`BatchComparison`**: Model-level paired comparison between two named batches. Uses Wilcoxon signed-rank across models.

#### `accuracy_comparison.py`
- **`AccuracyComparison`**: Fisher's exact test comparing two groups (e.g., `has_vignette_text=True` vs `False`) across every (model, unit) combination, with Bonferroni correction.

#### `cross_experiment_comparison.py`
- **`CrossExperimentComparison`**: Mann-Whitney U test comparing per-unit accuracy distributions between two experiments (e.g., random-dose vs empty vignette).

#### `cross_experiment_matched.py`
- **`CrossExperimentMatched`**: Identifies opioid pairs that appear in both random-dose and vignette experiments, then runs matched Wilcoxon and Spearman rank-correlation comparisons.

#### `icc_analysis.py`
- **`ICCAnalysis`**: Computes ICC(1,1) for each (model × scenario), measuring how much vignette wording accounts for variance in log(observed/expected). Uses one-way random-effects ANOVA.

#### `kendall_w.py`
- **`kendall_w(rankings_matrix)`** *(function)*: Computes Kendall's W (coefficient of concordance) and chi-squared p-value.
- **`compute_kendall_w_for_scenarios(results_csv, output_csv, filters)`** *(function)*: Applies it across scenarios, treating models as raters.

#### `model_ranking.py`
- **`ModelRanking`**: Ranks models using Cochran-Mantel-Haenszel (CMH) stratified tests on all pairwise comparisons, with Bonferroni correction. Produces adjusted ranks where models not significantly different share a rank.

#### `model_means.py`
- **`ModelBatchMeansBuilder`**: Computes per-(model, batch) mean tight/broad accuracy and weight. Used to prepare data for batch comparison and bar charts.

#### `per_model_wilcoxon.py`
- **`compute_per_model_wilcoxon(comparison_csv, output_csv)`** *(function)*: Per-model and pooled Wilcoxon signed-rank tests on pre-computed difference columns.

#### `text_effect.py`
- **`TextEffectDifference`**: Computes Δ(empty − text) in tight/broad accuracy per model × prompt condition × OME level.
- **`TextEffectSignificance`**: Thin wrapper around `AccuracyComparison` for the text-vs-empty comparison.

#### `variance_icc_stats.py`
- **`compute_variance_icc_spearman(icc_csv, vignette_model_csv, output_csv)`** *(function)*: Spearman ρ between scenario variance and ICC, including per-model and overall estimates, plus a binomial sign test.

#### `grid_independence_tests.py`
- **`compute_grid_independence_tests(icc_csv, vignette_model_csv, output_csv)`** *(function)*: Chi-square independence tests for 3×3 grids (accuracy × variance, variance × CV, variance × ICC).

#### `performance_profile.py`
- **`compute_random_dose_profile(model_csv, output_csv, ...)`** *(function)*: Classifies each (model, pair) result into: correct, precise-wrong, other-wrong, dose-dependent-negative, dose-dependent-positive.
- **`compute_vignettes_profile(model_csv, output_csv, ...)`** *(function)*: Classifies vignette results into: correct, precise-wrong, imprecise.

#### `statistical_methods.py`
- Generates a self-contained HTML document (`figures/statistical_methods.html`) listing every statistical test used, with test statistics, p-values, sample sizes, figure references, and links to source code and result CSVs.

## Setup

1. Copy `.env.example` to `.env` and populate API keys:
   ```
   OPENAI_API_KEY=...
   OPENROUTER_API_KEY=...
   ANTHROPIC_API_KEY=...
   GROQ_API_KEY=...
   GOOGLE_API_KEY=...
   ```
2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
3. Run the full pipeline from the repository root:
   ```bash
   python orchestration/run_experiments.py
   python orchestration/run_analysis.py
   python orchestration/generate_summaries.py
   ```
   Or open `opioid-conversion.ipynb` for interactive exploration.
